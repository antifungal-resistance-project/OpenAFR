# Design: Refocus OpenAFR on resistant-CYP51 triage; wall off FKS1 surveillance

Generated by /office-hours on 2026-08-21

Repo: antifungal-resistance-project/OpenAFR
Status: DRAFT
Mode: Builder

## Problem Statement

OpenAFR carries two products in one repo and the seams are blurred: a validated
structural drug-discovery tool (geometry-over-docking triage against CYP51 / azoles,
the original core) and a newer genomic early-warning surveillance track that has itself
pivoted from ERG11/azoles to FKS1/echinocandins (detection-only). The owner wants to
know whether the project is focused on the right thing and whether the code is confusing
because of the split. Stated ambition: use OpenAFR to help bring a new antifungal to
market, partnering with an academic wet lab or CRO for the physical assays.

## What Makes This Cool

The durable, rare asset is not a molecule — it is the **self-validating discipline**:
a pre-registered, hash-frozen, blind-holdout, permutation-tested screen with a gate that
blocks the run unless it re-discovers known drugs it has never seen. Almost no amateur
(or academic) docking repo proves its ranking means anything before publishing a list.
That credibility layer is the thing that could get a wet-lab PI to answer the email.

## Constraints

- Solo builder, computational only. No wet lab, no synthesis, no assays in-house.
- "Bring a drug to market" is a 10-15 year, nine-figure, ~40-step road. OpenAFR is
  step ~0.5: triage. Realistic near-term output is a *credible shortlist a wet lab acts on*,
  not a clinical candidate.
- The self-validation gate REQUIRES known actives to hide and re-discover. This hard
  constraint rank-orders every target choice.
- Apple-silicon dev box; the reads→consensus surveillance tooling (bioconda) needs a
  Linux/x86 host. (Carried from prior work; not central to this refocus.)

## Premises (agreed this session)

1. OpenAFR's durable asset is the **self-validating method + credibility discipline**,
   not any single molecule.
2. Best drug target is **resistant CYP51** (the mutant Y132F / K143R / etc. pocket),
   screened against a **repurposing / known-drug library** — not novel targets, not FKS1,
   not new wild-type azoles.
3. **FKS1 surveillance is a separate product** for a separate user (hospital
   epidemiologist, not med-chemist) and should be walled off or spun out, not blended
   into the drug-discovery pitch.
4. **Step 1 is a wet-lab "yes,"** earned by a validated shortlist *plus the evidence the
   ranking is trustworthy* — lead with the validation, not the list.

### Why not the two obvious targets (ruled out this session)

- **Novel target** — has no known drugs, so the validation gate cannot run. It destroys
  the exact discipline that is the project's only real edge. Rejected.
- **FKS1 / echinocandins for the *drug* tool** — giant multi-pass membrane enzyme,
  macrocyclic lipopeptide ligands dock poorly, only a handful of known actives (weak
  holdout), and the heme-coordination geometry trick does not transfer. Good target for
  *surveillance* (detection needs no docking); bad target for structural triage. Rejected
  for the drug tool, kept as the surveillance track.

## Approaches Considered

### Approach A: Validate the foundation first (minimal viable)
Prove the existing gate can still re-discover known azoles/tetrazoles on the *resistant
mutant* pocket (using the auris ERG11-port structures) — blind holdout + permutation test,
same rig as Track 1, on the mutant active site. Answers the make-or-break question cheaply
before any screen. Reuses the validation gate, ERG11-port structures, permutation harness.

### Approach B: Split the products, sharpen the thesis (structure move)
Cleanly separate OpenAFR-triage (CYP51 drug discovery) from the FKS1 surveillance product.
Rewrite README/VISION to one crisp thesis. Directly fixes the "confusing code." Low risk,
mostly reorganization + docs.

### Approach C: Build the full wet-lab-ready package (ideal architecture)
A + the resistant-pocket repurposing screen → a validated shortlist → a one-page
collaboration proposal aimed at a specific named lab, led with the validation evidence.
Produces the actual step-1 artifact. Depends on A passing.

### Lateral option (noted, not chosen): method-as-product
Publish a public "resistance-aware triage benchmark" other antifungal groups run their own
molecules through — become the field's trusted validation layer instead of a drug hunter.
Leans all the way into credibility-as-differentiator. Parked for now.

## Recommended Approach (LEAN — revised after eng review + outside voice, 2026-08-21)

The eng review found Phase A was already built and run. The outside-voice pass then found
the original A→B→C plan was largely off the critical path for the only goal (a wet-lab yes)
and rested on a circular validation. Both cross-model reviews agreed; the user accepted all
recommendations (D5→B, D6→B, D7→B). The plan collapses to a leaner, more honest version.

**The reframe that drives everything (outside-voice #1 — the resistance-breaker gap):**
The gate re-discovers 7 *known azoles that Y132F/K143R clinically defeat*. Ranking defeated
drugs highly does NOT show the tool can find novel resistance-*breakers* — which is exactly
what a wet-lab shortlist claims. And mutant AUC 0.805 ≈ WT 0.794 means the criterion is
nearly *insensitive* to the mutation. So "broad enrichment transfers to Y132F" is close to a
tautology and must not be pitched as "we can triage molecules that beat resistance." A
genuine resistance-aware claim needs actives that are *active against the resistant strain*
(or true novel hits), not the defeated azole panel.

**Lean sequence:**

1. **Expand the active set (highest-leverage cheap fix).** n=7 actives is too thin for any
   AUC/EF@5%/permutation claim on the mutant pocket (EF@5% "5.63x" is ~18 molecules; one
   active shifts it ~1.4x). Add newer tetrazoles designed against resistant strains
   (oteseconazole/VT-1598) and any compounds with measured activity vs resistant *C. auris*.
   This is the single change that makes any downstream number defensible.
2. **Keep Y132F as an honest NEGATIVE (D5→B — do NOT re-grade).** Leave
   `RESULTS_auris_Y132F.md` reported as a FAIL. Add a separate, clearly-labeled durable-metric
   *reading* (AUC transfers; top-rank enrichment does not) WITHOUT flipping the pre-registered
   verdict. Re-grading a sha-frozen FAIL into a pass is the exact move pre-registration exists
   to prevent. The honest negative is a *more* distinctive pitch than a manufactured pass.
3. **Build the wet-lab package (C).** A shortlist + one-page collaboration proposal led with
   the honest validation story — including the Y132F negative as evidence of discipline
   ("I ran the does-it-still-work-on-the-mutant check almost no docking repo runs, and
   reported it honestly"). Address it to one named lab.

**Deferred until a PI actually pulls them (not on the critical path):**
- **A2 repacker + K143R (D6→B):** the determinism gate proves reproducibility, not
  correctness, and there is no experimental K143R structure to validate the rotamer against —
  a deterministic-but-wrong receptor would feed a confidently-wrong result. `mutate_receptor.py`'s
  own creed ("a silently guessed side chain is worse than none") argues against it. Plus the
  decoy-driven top-rank ceiling makes the K143R outcome near-foregone. Keep refusing atom-adding
  mutations.
- **B `openafr/core/` extraction (D7→B):** the surveillance→triage coupling is one-directional
  and benign (a consumer depending on a core), not a tangle. Document the layering in a module
  docstring now; defer the broad refactor until the code needs it.

## Open Questions

- **What is the honest pass bar for a resistant-pocket transfer?** The project already
  concluded EF@1% is noise and AUC/EF@5% are durable. A1 should re-grade Y132F on that bar;
  the auris pre-registration's EF@1% clause needs a recorded deviation noting it leans on a
  since-discredited metric.
- **Can a deterministic repacker exist in the pinned env?** No PyMOL/FoldX/SCWRL today. A2's
  feasibility hinges on finding a repacker that is reproducible by construction or refusing.
- **Known-actives set breadth.** The current holdout is 7 azoles + property-matched decoys.
  Are newer tetrazoles (oteseconazole / VT-1598) in the set, and is 7 actives enough for a
  defensible permutation test on the mutant pocket?
- **Repurposing library choice for C.** Reuse the Drug Repurposing Hub run, or a library
  tuned to the resistant pocket?

## Success Criteria (lean)

- **Expanded active set:** the holdout includes resistant-strain-relevant actives (tetrazoles
  / measured-active-vs-resistant compounds), not just the defeated azole panel; n is large
  enough that EF@5% doesn't swing on a single molecule.
- **Y132F honesty:** `RESULTS_auris_Y132F.md` stays a reported FAIL; a separate durable-metric
  reading is added without altering the pre-registered verdict.
- **C:** a shortlist + one-page wet-lab proposal that leads with the honest validation story
  (including the Y132F negative), does NOT overclaim resistance-breaker discovery, and is
  addressed to one named lab.
- **Deferred work is documented, not done:** a module docstring records the triage/surveillance
  layering; `mutate_receptor.py` still refuses atom-adding mutations with a pointer to the
  deferred repacker rationale.

## NOT in Scope (considered, deferred)

- **Two-repo split + published `openafr-core`** — premature for a solo builder; revisit if
  surveillance ever spins out (D3 option B).
- **Novel targets and FKS1 as a *drug* target** — ruled out earlier; FKS1 stays surveillance.
- **Non-deterministic repacker with recorded seed** (D4 option C) — rejected; breaks the
  hash-frozen contract that is the project's credibility.
- **Local docking runs** — `vina`/`obabel` are absent on osx-arm64; all A1/A2 docking runs
  on the cloud Linux/x86 VM (same constraint as the ERG11 re-caller).
- **Collapsing the 7 `validate_gate*.py` scripts into a data table** — the per-run scripts are
  frozen provenance (each pins its own pre-registration hash); keep them.
- **A2: deterministic side-chain repacker + K143R/F126L transfer test (deferred, D6→B)** — the
  determinism gate proves reproducibility, not correctness; no experimental K143R structure
  exists to validate the rotamer; the decoy-driven top-rank ceiling makes the outcome
  near-foregone; and it's off the critical path for the wet-lab goal. Revisit only when a PI
  asks for clade-I specifically. `mutate_receptor.py` keeps refusing atom-adding mutations.
- **B: `openafr/core/` extraction (deferred, D7→B)** — the surveillance→triage coupling is
  one-directional and benign; a docstring documents the boundary at ~1% of the refactor's
  regression risk. Extract only when the code actually needs it.
- **Re-grading Y132F to a pass (rejected, D5→B)** — flipping a pre-registered sha-frozen FAIL
  into a positive is the cardinal pre-registration sin, even with a defensible metric.

## Failure Modes (per new codepath)

- **A2 repacker nondeterminism** — same input yields different receptor across env changes.
  Test: same-input→same-sha256. Error handling: refuse on nondeterminism. Without it: a
  silent, unreproducible receptor poisons every downstream result. **Critical if untested.**
- **B core-extraction import breakage** — `alert.py` structural verdict silently broken by a
  moved import. Test: full suite green + an `alert.py` structural-so-what integration test.
- **A1 metric mis-grade** — re-running on EF@1% again would re-log a meaningless FAIL. Guard:
  grade on AUC/EF@5%, record the deviation.
